## Highlights


### Faster config resolution

This release includes an updated version of `@eslint/config-array` with a faster implementation of config resolution. This is the step in which ESLint decides, for every file and directory it visits, whether the path is ignored and which objects in the config apply to it.

In our benchmark, which resolves the configs for 1,500 files against a typical flat config, this step is more than three times faster with POSIX paths and about 15% faster with Windows paths. The improvements, made primarily with AI assistance, include:

* A config object's `files` and `ignores` patterns are analyzed only once instead of once per file.
* Paths that cannot match a pattern's literal parts, such as the `src/` or `.js` in `src/**/*.js`, are rejected before the full glob match runs.
* For POSIX paths, a file's location relative to the base path is now computed more efficiently when the path is already normalized.

Config resolution is only one part of an ESLint run, so the effect on total lint time depends on your project. No changes are needed on your side.

### Rule improvements

The following rules have been updated to address edge cases or to make reported problem locations more intuitive:

* [`accessor-pairs`](/docs/latest/rules/accessor-pairs)
* [`default-case`](/docs/latest/rules/default-case)
* [`func-names`](/docs/latest/rules/func-names)
* [`no-invalid-this`](/docs/latest/rules/no-invalid-this)
* [`no-prototype-builtins`](/docs/latest/rules/no-prototype-builtins)
* [`no-shadow`](/docs/latest/rules/no-shadow)
* [`no-unneeded-ternary`](/docs/latest/rules/no-unneeded-ternary)
* [`no-useless-rename`](/docs/latest/rules/no-useless-rename)
* [`prefer-arrow-callback`](/docs/latest/rules/prefer-arrow-callback)
