## Highlights

Several core rules have been updated to report more linting problems.

### `no-use-before-define`

The [`no-use-before-define`](/docs/latest/rules/no-use-before-define) rule has been updated to account for the fact that IIFEs execute immediately by treating them as part of the execution context where they are defined and called.

This change can produce more linting errors in cases such as the following:

```js
/* eslint no-use-before-define: ["error", { variables: false }] */

(() => {
    console.log(foo); // 'foo' was used before it was defined.
})();

const foo = "bar";
```

### `no-obj-calls`

The [`no-obj-calls`](/docs/latest/rules/no-obj-calls) rule has been updated to report calls to `globalThis`.

```js
/* eslint no-obj-calls: "error" */

const foo = globalThis(); // 'globalThis' is not a function.

const bar = new globalThis(); // 'globalThis' is not a function.
```

### `no-unsafe-optional-chaining`

The [`no-unsafe-optional-chaining`](/docs/latest/rules/no-unsafe-optional-chaining) rule has been updated to report unsafe usage of optional chaining in arguments of `yield*`.

```js
/* eslint no-unsafe-optional-chaining: "error" */

function* gen() {
    yield* obj?.foo; // Unsafe usage of optional chaining. If it short-circuits with 'undefined' the evaluation will throw TypeError.
}
```
